# Routine Property Inspections — Plan

A second accountability pillar alongside vacancies. Where vacancies measure
**turn speed**, routine inspections measure **ongoing upkeep** — proof the
property manager is physically visiting on a cadence and documenting condition
(curb appeal, weeds, trash, parking, exterior, roof, safety).

Same DNA as vacancies: a committed schedule → photo evidence → green/yellow/red
status → escalating reminders → property-manager scorecard.

## Decisions (locked)

1. **Needs-attention items are flagged**, not turned into tracked remediation
   deadlines (that's a future, monetizable Phase 2). They surface in the UI and
   count as "open issues" on the scorecard.
2. **One active schedule per property.**
3. **Owner visibility** via the dashboard + scorecard. Owner email summaries are
   deferred.
4. **Full cadence list**: weekly / monthly / quarterly / semiannual / annual.

## Data model (all `org_id`-scoped, RLS like the rest of the app)

- `inspection_schedules` — one recurring schedule per property
  (`frequency`, `anchor_date`, `next_due_date`, `manager_id`, `active`).
- `property_inspections` — a single occurrence (generated by cron or ad-hoc)
  (`due_date`, `completed_at`, `completed_by`, `overall_notes`).
- `property_inspection_items` — one row per checklist area
  (`area_key`, `result` = pass | needs_attention | na, `notes`).
- `property_inspection_media` — photos linked to an item.
- `inspection_reminders` — parallel to `reminders` so vacancy reminders are
  untouched.

New enums: `inspection_frequency`, `inspection_item_result`. Reuses the existing
`reminder_type` enum.

Storage: a new private `property-media` bucket, keyed `{org_id}/{inspection_id}/
{filename}` — same policy pattern as `vacancy-media`, so signed-URL viewing
reuses `MediaGallery`.

## Default checklist (code constant — `src/lib/inspection-checklist.ts`)

Curb appeal · Landscaping & weeds · Trash & dumpster · Parking lot & drive ·
Building exterior · Common areas / hallways · Roof & gutters · Safety & exterior
lighting · Signage & entry. Each item: result + notes + ≥1 photo (unless N/A).
Owner-customizable templates is the obvious next step.

## Logic (pure, unit-tested — `src/lib/inspections-calc.ts`)

- `routineInspectionStatus()`, `advanceScheduleDate()`, `inspectionScorecard()`.
- Auto-generation: the daily Vercel cron creates due occurrences from active
  schedules and rolls `next_due_date` forward.
- Reminders reuse the escalation ladder, emailed to the responsible manager via
  `inspection_reminders`.

## Screens

- Sidebar: **Inspections**.
- `/inspections` — work queue (upcoming + overdue) and completed history.
- `/inspections/[id]` — complete-inspection flow (checklist + photos + notes).
- Property detail — schedule card + inspection history.
- Owner dashboard — "Inspections overdue" stat.
